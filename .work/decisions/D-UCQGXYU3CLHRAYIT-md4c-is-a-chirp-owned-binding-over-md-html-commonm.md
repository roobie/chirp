# D-UCQGXYU3CLHRAYIT md4c is a chirp-owned binding over md_html, CommonMark by default

## Context
The GitHub Pages site (U-F35YV2DPMJION4EG) had to be generated by chirp from the repo's Markdown, and chirp could not render Markdown. Scripts that turn notes or changelogs into HTML meet the same gap.

## Decision
chirp bundles md4c and owns a small binding over its HTML renderer, as a module named `md4c`. Plain CommonMark is the default and every extension is opt-in, with `:github` as a shorthand. An unknown option is an error. md4c's own global symbols are renamed at build time.

## Why
md4c is MIT, small (two C files and an entity table, no dependencies) and CommonMark-conformant, with tables, footnotes and the other GitHub extensions built in; lk, another single-binary runtime, bundles it for the same reasons. cmark is the reference but needs cmark-gfm for tables, a larger fork. A private renderer inside the site would have been a partial Markdown that chirp maintains forever, and a site generator in Node or Ruby a second toolchain. CommonMark by default means a document renders the same as in any conformant tool; the extensions change meaning (`~` and `|`), so they are asked for. An unknown option failing catches a misspelt flag that would otherwise silently render differently. The renames follow L-BVXC557ZOWPP4SN5: `entity_lookup` is a name another C library could plausibly also define.

## Consequences
- Raw HTML passes through by default, as CommonMark specifies; untrusted text needs `:no-html`.
- Only HTML output is offered. md4c's parse events cannot rebuild Markdown byte for byte, so round-trip editing stays B-7H6ASKHIBTAYW7NL and would build on source offsets, not on this API.
